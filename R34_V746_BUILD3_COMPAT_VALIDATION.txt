ROOT CAUSE CONFIRMED
--------------------
- Build 3 is Manifest V3, version 0.2.7, installed unpacked.
- Its manifest has no top-level manifest.key identity pin.
- It uses the legacy endpoints /extension/v3/key and /extension/v3/check-status.
- The check-status request is an application/json POST from the extension runtime.
- R32/R33 pre-hotfix strict CORS accepted only fixed ZVM_EXTENSION_IDS.
- Unpacked Chrome extension IDs without manifest.key may vary by installation,
  making a finite global Extension ID allowlist insufficient for existing Build 3 copies.
- The failure occurs at extension-origin/CORS policy before the legacy business logic,
  while Build Authority remains a separate V4/Protocol V2 authority layer.

R34 FIX
-------
- extension-origin-policy.js parses only syntactically valid chrome-extension:// IDs.
- Official allowlisted IDs continue to work on all permitted extension routes.
- An unlisted unpacked extension ID is reflected ONLY when:
  * ZVM_LEGACY_V3_ALLOW=true; and
  * path is exactly /extension/v3/key or /extension/v3/check-status.
- There is NO second environment switch in R34.
- /extension/v4/*, Build Authority, Registry V2, signed DEV, admin, analytics, Meta,
  and all other V3 paths remain strict.
- License/key validation, expiration, blocking, activation limits, phone rules and
  rate limits are unchanged.
- No Build 3 client update/reinstall is required.
