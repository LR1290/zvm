# R46.92 — Integridade administrativa e exportação canônica

## Incidente / achados

A API de dados do Admin já usa `readAdminKeysSnapshot()` para exibir estado persistido, mas a exportação CSV de licenças e o endpoint de exclusão em lote ainda liam o cache `keys` em memória. Quando uma instância é reiniciada ou outro escritor altera chaves, operações poderiam exportar dados defasados ou omitir chaves existentes na seleção.

A exclusão individual também não possuía `requireSameOriginPost` (proteção CSRF adicional) e respondia `ok:true` mesmo quando o campo da chave já não existia no MongoDB.

## Correções de backend

- **CSV:** captura snapshot do MongoDB na própria requisição, falha com HTTP 503 + JSON no caso de perda de leitura; `Cache-Control: no-store` e cabeçalhos de segurança. Nunca exporta snapshot local silenciosamente.
- **Exclusão individual:** exige sessão e mesma origem, lê licença canônica, retorna 404 se inexistente e executa `$unset` com predicado `$exists:true`; sem confirmação de match não altera cache local nem declara sucesso.
- **Exclusão em lote:** valida a lista integralmente (até 200 códigos exatos, sem truncamento/sanitização silenciosa), deduplica sem alterar identidade, confirma a existência de todos no MongoDB e usa um único `updateOne` com predicados de existência para todas as chaves. Uma chave ausente impede a exclusão de todo o lote; conflito real retorna HTTP 409. Ações sem confirmação não são repetidas automaticamente.
- Nenhuma alteração direta nos clientes foi realizada durante desenvolvimento/teste.

## Correções de interface

- Proteção contra duplo clique na exclusão individual e em lote; após resultado desconhecido, executa somente atualização/leitura.
- Seleção oculta por filtro é desmarcada; lote só usa linhas visíveis.
- Exportação CSV rejeita respostas JSON/503, não salva HTML/JSON com extensão `.csv` e revoga Blob URL após prazo seguro.
- Limpeza de logs em operação única e com reconciliação de estado.
- Tratamento de falha incerta no acesso DEV e contadores de usuários que não deveriam refletir quantidade filtrada.
- Asset novo `zvm-admin-dashboard.aba4a5628fd6.js` com SHA-256 `aba4a5628fd6d6554e6ab3a18cacafc7ac2c3c3e5ff2d8a93205a520e6739ecd`; versão anterior preservada apenas para URLs `immutable` em abas antigas.

## Verificação

`npm run check` agora inclui `tests/r46-92-admin-authority.test.js`, com mock Mongo e proteção contra exclusão parcial, rejeição de códigos malformados, CSRF e exportação fail-closed.

## Riscos não cobertos

- O documento único `zapvoice.store.keys` ainda concentra as licenças; migração para coleção por chave precisa de projeto independente, compatibilidade com clientes legados e rollback.
- Testes automatizados não substituem ensaio autenticado no navegador para todos os controles de segurança, IP blacklist, e relatórios.
- Falha de confirmação na exclusão exige consulta posterior, nunca reenvio automático.
