# R46.88 — Incidente de conflitos falsos no Admin (16/10/2026)

## Evidências de produção
- Capturas do operador: falhas ao editar DEV, USOS e RENOMEAR, com aviso \`key_write_conflict\`. Renovação também foi relatada; **não havia nas capturas prova isolada de falha no caminho de renovação**, que usa helper independente.
- Render \`srv-d8co50mq1p3s7390p80g\`, baseline R46.87 commit \`838b601b44980927c5b361b87a60b7024db07e02\`: log \`[ADMIN] phones persist: key_write_conflict\` em **2026-10-16T18:40:23Z**.
- Mongo \`zapvoice.store\`, leitura sem alterações: 61 licenças no mapa, cinco com campo interno \`updatedAt\` em **BSON Date**. Na igualdade do registro inteiro, converter Date para string ISO elimina a correspondência; comparação apenas do \`label\` segue válida.
- Fonte: \`server.js\` R46.87, \`mutateAdminKeyRecordStrict\` comparava todo \`data.<code>\` contra uma cópia JSON e repetia a comparação integral até cinco vezes.

## Causa raiz
1. Igualdade de subdocumento com todos os campos misturava formatos BSON e JSON, gerando rejeições sem concorrência legítima.
2. Mudanças rotineiras de telemetria, telefone e atividade impediam alterações de outros campos, mesmo quando perfeitamente independentes.
3. A rota de remoção de telefones mascarava conflitos reais como erro 503 de indisponibilidade.

## Correções
- \`mutateAdminKeyRecordStrict\` calcula **somente os campos efetivamente alterados**, inclui precondições CAS apenas nesses campos e utiliza \`findOneAndUpdate\` com \`returnDocument:'after'\`. O restante do documento nunca é sobrescrito.
- \`modules\`: granularidade por módulo; \`phones\`: CAS da lista/atributos efetivamente mutados; o máximo continua sendo cinco tentativas apenas para CAS confirmado sem correspondência.
- Erros de rede incertos **não são repetidos** automaticamente.
- Rota \`/api/keys/:code/phones\` devolve erro 409 para conflito verdadeiro em vez de 503 genérico. Nenhuma verificação de autenticação, CSRF ou autorização foi removida.
- O acréscimo de duração permanece em \`renewAdminKeyAtomicStrict\`, implementação separada introduzida na R46.87.

## Evidências de teste
- 12 cenários Node em ambiente local: BSON Date, edição durante telemetria, disputa do mesmo campo, módulos distintos, remoção de telefone e disputa de lista, cinco conflitos CAS, falha de rede incerta, no-op, módulos nulos, remoção de propriedade e alteração de bloqueio.
- Parser V8: \`server.js\` completo da branch, teste R46.84 e teste R46.88 aprovados.
- Fixture administrativa R46.37 e teste de rede R46.80 adaptados; R46.88 incluído no \`npm run check\`.
- O `npm run check` foi executado em CI tanto na `main` R46.87 original quanto na branch R46.88; ambos falham no teste CSS preexistente `tests/r46-system-ui.test.js:33` (Analytics). Os seis testes administrativos isolados foram aprovados, incluindo os 12 cenários R46.88. Excluindo o teste CSS há outro teste antigo com dois assets de dashboard (`tests/r46-35-release-hardening.test.js`). Permanecem pendentes o deploy controlado e a homologação autenticada em licença exclusiva de QA. Não declarar correção de produção antes desses gates.

## Homologação pós-deploy
1. \`/ready\` e logs sem aumento de 409/503.
2. Em chave de homologação (nunca cliente real): DEV, USOS, RENOMEAR, módulos, duração, dispositivos e telefones; comparar antes/depois para evitar perda de \`expiresAt\`, \`active\` e \`phones\`.
3. Simular atualização concorrente somente em QA; confirmar alterações independentes persistidas e conflito real rejeitado.
4. Em resposta ambígua por falha de rede, atualizar o painel antes de repetir qualquer comando.
